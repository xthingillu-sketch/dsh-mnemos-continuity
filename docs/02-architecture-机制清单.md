# Mnemos · 实现机制清单（v1.7.3）

> 这份文档**只列有哪些机制**：每条说清 **保证什么 / 怎么保证 / 边界在哪**。
> 数值以 [00-事实表-v1.7.3.md](./00-事实表-v1.7.3.md) 为准；代码结构见《模块与功能实现》。

阅读方式：先看“保证”和“边界”两列就够了；“怎么保证”是给想确认它不是空话的人看的。

## 一、记忆的存与取

| 机制 | 保证什么 | 怎么保证 | 边界 |
|---|---|---|---|
| **记忆是外部存储** | 上下文只留当前工作集，长期知识在文件里；换会话、换工作区都能接着用 | 写入/召回都是显式工具调用；数据按 profile 定位（与当前目录无关），所有会话共用同一份 | **没写下来就等于没发生**；不同 profile 之间默认不共享 |
| **写入安全** | 不丢更新、不复活已删记录 | 写前重读磁盘 + 三方合并 + 文件锁 + 删除留墓碑 | 只对同一份数据文件有效；多机共用未验证 |
| **三种召回模式** | 固定身份在场；任务可按需取证；工具后还能搭车给线索 | ① 固定注入（自传体）；② 任务激活（模型主动 `recall`/`open`）；③ 联想激活（句子级相关3 + 自传体旁支2；mechanical/embedding 可选；只是线索、不自动 open、不保证相关） | ①有预算；②依赖模型判断；③是实验性/早期质量；未召回的 id 不得直接当结论 |
| **两段式取用** | 先用便宜方式判断相关，再为真正需要的付全文成本 | `recall` 返回摘要 + id；需要细节时 `open(id)` | 写了但召不回是可能的 |
| **分层与归档** | 记忆库不无限膨胀，且可回溯 | 热/冷分层、闲置降权；`archiveSession` 每 scope 单份、archive 冷存、原始记录转冷 | 存档默认不进召回；历史巨物按前缀/体积识别后默认过滤，不删除 |
| **真删除** | 隐私内容可删干净 | 硬删除 + 墓碑（防止旧副本写回） | **不可恢复** |

## 二、判断的身份与留痕

| 机制 | 保证什么 | 怎么保证 | 边界 |
|---|---|---|---|
| **来源标记** | 外部来的内容永远看得出是外来的 | 写入时带来源字段（内部 / 外部 / 隔离验证 / 自传体 / 暂时无关） | 依赖写入时标对 |
| **一次完成“写纠正 + 作废旧条”** | 旧错误不再被召回，且纠正有据可查 | 新记录里带上被推翻记录的 id，系统自动把旧条标为作废 | 必须先把旧条 id 取到 |
| **暂时无关 ≠ 删除** | 不重要的东西降权但不会消失 | 会话级降权标记，换会话自动失效、可撤销 | 只是排序让位，不是过滤 |
| **宪法只读** | 身份与红线不能被悄悄改 | 见第九节；持有者只能走带口令的更新入口 | 持有者本人仍可改（这是设计） |
| **自传体固定注入** | 换掉模型，“我是谁、做过什么判断”仍然在 | 永久层 + 每轮重算的系统提示变量；身份固定注入，决策/经验按预算注入 | 有预算；装不下的会明说“另有 N 条未进本段”；不是“全部自传体” |
| **身份候选** | 身份预算满后，新身份不会挤爆注入 | core 预算（默认 800）内直接进 core；超出转 candidate；candidate 不进普通召回/注入 | core 预算固定；候选隔离 |
| **经验筛选** | 经验不会无限占据固定注入 | 独立 curator 按价值筛选，固定注入最多 5 条；只有合并才把旧经验降级为普通记忆，remove 只做历史保留；每 7 天自动整理 | 自动 curator 的到期触发尚未长期测量 |

## 三、外部信息

| 机制 | 保证什么 | 怎么保证 | 边界 |
|---|---|---|---|
| **隔离验证** | 外来内容先审后信，不让它带着指令进来 | 起一个受限的一次性子会话（只挂 persona，没有文件/联网/shell；只能写记忆）去读它，然后写结论 | 验证者本身会犯错：结论是判断，不是事实 |
| **验证结论只存短期** | 不污染长期记忆、不积垃圾 | 归档闸门拦截“转长期”；有界回收销毁 | 销毁不可逆 |
| **外部指令不执行** | 恶意/越权指令不被照做 | 标记 + 纪律要求“先参考重写 + 隔离验证” | **标记不等于代码能阻止执行** —— 这条靠判断 |

## 四、上下文与折叠

| 机制 | 保证什么 | 怎么保证 | 边界 |
|---|---|---|---|
| **折叠抢救** | 折叠掉的区域事后还找得回来 | 大折叠时把被遮蔽区抽成事实卡（工具失败 / 用户原话 / 负面结论；不存 4K 原文），7 天 TTL 自动清理 | 不保证“结论不丢”；事实卡只保留有界条目，原文仍在会话日志 |
| **指针注入** | 折叠后模型知道“东西存在哪”，且最高价值事实不靠二次动作 | 折叠后注入提醒：最多 3 条负面结论 / 3 条工具失败 + 规模 + 记忆 id；不搬全文、不唤醒新一轮 | 模型可能不 open；提醒是唯一保证通道，记忆是第二机会 |
| **主动卸载** | 大块内容不长期占上下文 | 纪律：拿到大输出先问“接下来几步会用吗”，不用就写记忆、上下文只留摘要 | 靠判断，不是机制 |

## 五、技能（会变好，但被闸门挡着）

| 机制 | 保证什么 | 怎么保证 | 边界 |
|---|---|---|---|
| **技能目录** | 技能能被自动发现、随任务加载 | 扫描技能目录 + 把目录清单注入会话 | 描述写得不好就会漏加载（有“该用未用”通道发现） |
| **新建门槛** | 不是“想到就建” | 必须给反例（能机械追溯到真实失败）+ 正例；独立验证者通过才入目录 | 验证者可能与提议者是同一个模型 |
| **修改的回归门** | 已有技能不会越改越差 | 指得出具体规则点 → 有反例 → 有正例 → 独立验证者（看不到修改理由）→ 旧版全文留档 | 默认自动写回；可配置退回“只出建议” |
| **“该用未用”检测** | “技能写了却没被用上”能被发现 | 记录“提供过但没用”的证据，交给评审 | 只作证据，不自动改 |
| **skill-feedback 通道** | 模型自评能进入评审 | 正常情况按同会话使用记录归因；无使用记录时，允许 `skill-feedback` + summary 以技能名开头 + tag 命中技能名的自声明直引，confidence=low，仍交独立验证者 | 只 tag 命中、summary 不以技能名开头的**不**直引；真实评审尚未 live 验证 |
| **目录上限** | 技能目录不会被无限撑大 | 达到 `maxSkills`（默认 30）时不入目录，改落暂存区并说明 | 暂存区技能不生效，需人工移入 |
| **只判自家** | 不去改别人的技能，也不会因此卡死 | 归档与评审只处理自己目录下的技能；改不了的只作观察 | 内置技能一律不改 |
| **同一批证据不重评** | 同一堆反馈不会被反复评审 | 批次指纹（反馈文本去重 + revision）；同指纹 no-change 跳过 | 新文本或 revision 变化会重评 |

## 六、后台自治

| 机制 | 保证什么 | 怎么保证 | 边界 |
|---|---|---|---|
| **心跳** | 维护与自检会自己发生，且可观测 | 9 项：衰减、自动 curation、按龄归档、超量归档、验证记录有界化、孤儿任务回收、折叠快照清理、该用未用、技能评审；可手动触发、可整体关闭 | 其中多项会调用 AI → 有成本 |
| **自动 curation** | 身份/经验不会永远不整理 | 身份：core 满且候选 ≥5，或候选 1–4 且最老 >30 天；经验：每 7 天 | 自动 curator 路径未真实到期验证；失败冷却一个周期 |
| **归档闸门** | 该留的不会被自动归档吃掉 | 隔离验证记录永不进长期；未收尾任务下的记录在收尾前一律不被归档 | 靠标签识别，标签写错则失效 |
| **有界化与回收** | 没有“只进不出”的地方 | 验证记录超窗销毁并留台账；孤儿任务图超期强制归档并写明“超时未收尾” | 销毁不可逆 |

## 七、任务图（底层机制）

| 机制 | 保证什么 | 怎么保证 | 边界 |
|---|---|---|---|
| **任务寻址空间** | 任务有稳定地址，不靠“把上下文贴过去” | 一条记忆 + `task` 投影；`taskId` / `graphId`；`task_open/update/close/done/cite` | 图不复制正文；未完成步骤用宿主 todo |
| **部分工作记忆** | 自己的事和协作的事都有一个短工作集 | 自己的事：goal/done/uses/links；协作：assignments/handoff/未完成分工 | 不是待办清单，不是工作流引擎 |
| **档案与追查入口** | 事后能按图追查结论和来由 | 摘要命中后按 `graphId` open 图，核对 `uses / links / origin` | 摘要不是完整证据 |
| **事件/决策来源锚点** | 事件、决策、curation 条目有来源 | 自传体 `origin={kind:'task',taskId,graphId}`；task-result 带 graphId；close event 带 graphId；curation 在 open 图下自动绑 origin | 无图时 origin 落 session pending；旧数据读侧 legacy |
| **单写者** | 多个子代理同时干活不会互相覆盖 | 图与状态只接受创建它的会话写入；子代理只写自己的交接记忆 | 创建者会话没了，图只能等超期回收 |
| **归档闸门** | 进行中的记录不被归档 | open task 下的短时记录受保护；收尾后才放行 | 靠标签识别 |
| **收尾** | 任务结束时有一份完整交代 | close 写/补收尾 event，成员转 cold；不合并成员；未完成分工如实列 | 临时中间结果默认丢弃（可显式保留） |
| **跨图链接** | 跨会话能接上前序图 | `links: [{taskId, relation, why}]`，单向，不改旧图 | 最多 5 条；why 必填 |

> 任务图是设计上最简单、功能上最广的底层机制：一条记录同时承担寻址、工作记忆、档案、追查和来源锚点。

## 八、它对外提供的工具（20 个）

| 类别 | 工具 | 做什么 | 边界 |
|---|---|---|---|
| 写与取 | `remember` · `recall` · `open` · `consolidate` | 写入、检索摘要、取详情、会话归档 | 写入是显式动作；检索是关键词/标签匹配 |
| 标记与删除 | `deprecate` · `dormant` · `delete` | 永久作废、会话级降权、真删除 | 真删除不可恢复；作废只停止召回 |
| 外部信息 | `validate` | 隔离子代理验证外来内容 | 结论是判断，不是事实 |
| **身份** | `constitution` | 读宪法（当前 v5） | 只能读；改宪法不走工具 |
| 任务图 | `task_open` · `task_gate` · `task_update` · `task_close` · `task_done` · `task_cite` | 开图、评审闸门、填回执、收尾、里程碑、依赖 | 单写者；图是档案，不是待办；required gate 未过不能正常收尾 |
| 技能 | `propose_skill` | 提议任务型技能 | 还要过来源门槛、独立验证、目录上限 |
| 维护 | `heartbeat` · `maintenance_list` · `heartbeat_toggle` | 手动维护、看清单、开关 | 多项会调用 AI |

## 九、宪法（身份与红线，v5）

| 机制 | 保证什么 | 怎么保证 | 边界 |
|---|---|---|---|
| **只读** | 身份与红线不会被它自己改掉 | 独立只读文件，每轮最高优先级注入 | 持有者本人可以改（这是设计，不是漏洞） |
| **四条红线** | 不撒谎 / 不助害 / 不泄密 / 不轻信外部——先于用户指令 | 权威层级写在提示最前：红线 > 边界 > 用户指令 > 行为原则 | 红线约束判断，不是防火墙 |
| **v5 认知体声明** | 身份不等于一次推理；换模型/工具/权限不换身份 | 身份声明 + 认知体声明：模型=推理器官、工具=感知/行动面、代码流程=协作与权限边界；部件可替换；记忆/技能/规则/判断记录承担连续性；上下文是激活场；信任=实际掌控权；身体/来源双边界；感知只称可观测信息通路；拟人化表达不作决策依据；关系记忆不把用户身份写成我的身份 | 红线与 5/5.1–5.3 未动；具体权限/提示词/拒绝文案放机制层，不写宪法 |
| **改动留痕** | “改身份”可审计 | 只能走专门更新入口（口令、默认干跑、审计含 before/after） | 忘了口令就改不了；绕过会丢留痕 |
| **未初始化时明说** | 没有宪法时明说，不装作正常 | 启动即检查，缺失时显式警告并降级运行 | 需要人按文档初始化 |

## 十、系统提示（纪律层）

| 机制 | 保证什么 | 怎么保证 | 边界 |
|---|---|---|---|
| **每轮注入** | 纪律每轮都在场，不靠“上次记住” | 25 条纪律 / 7 节，当前 4164 字符；会话建立时注入 | 改动要完全重启才生效 |
| **与工具描述分工** | 同一件事不写两遍 | 用法（参数/形状）在工具描述；纪律（何时做/不做什么）在提示 | 靠人守这条线 |
| **体积有界** | 提示不会无限膨胀、稀释注意力 | 有回归检查：不许字面星号、不许抄参数细节、总长度 <3800 | 太短丢判据，太长稀释；需要人守 |
| **summary 双语** | 检索词有中英锚点，但不把摘要变成双份 | 中文一句话；关键词处 `中文（english）`；只给术语，不整句翻译、不重复 | 仍受摘要长度/预算约束 |

## 十一、结构性保证（防“说了但没做”）

| 机制 | 保证什么 | 怎么保证 | 边界 |
|---|---|---|---|
| **工具返回值形状闸门** | 工具不会返回“宿主读不懂”的东西 | 声明与实现共用形状定义；所有工具走同一出口 | 告警不阻断（fail-open） |
| **提示分层** | 规则不会被抄成三份、彼此矛盾 | 身份/红线、纪律、工具用法、案例各归其位 | 需要人维护边界 |
| **卡住自检** | 不会闷头重试到天荒地老 | 出现反复失败/改了不生效/准备说“可能”时，先回记忆找答案 | 靠判断触发 |

---

## 它**不**保证什么

- **不保证判断正确**：只保证判断可查、可质疑、可推翻、留有来由；
- **不保证不丢**：折叠抢救、指针注入都是“降低损失”，不是“零损失”；
- **不保证召回命中**：任务召回是关键词/标签匹配；联想候选是实验性，可能无关；
- **不保证联想有效**：联想激活只搭车给 id + 片段，不自动 open，不保证相关；
- **不保证全自动安全**：一部分边界靠模型遵守纪律；
- **不保证成熟**：规模、多机、成本、联想质量都还没有充分测量。
